# Multi-Objective Candidate Scoring

**Ticket:** SURGE-PY-027 & SURGE-PY-029  
**Module:** `optimisation-python/app/optimisation/` (`scoring.py`, `scoring_models.py`)  
**Status:** Complete & Production-Ready  
**Dependencies:** `app.optimisation.engineering_metrics`, `app.costing.lifecycle`

---

## Overview

The `app.optimisation.scoring` module provides deterministic, multi-objective ranking and explainable recommendation of engineering candidates generated by the optimization engine.

It answers the primary engineering question:
> *“Among the set of structurally valid, electrically compliant candidate layouts generated for this wind farm, which network best optimizes physical, spatial, infrastructure, electrical, and lifecycle cost criteria under the user's weighted policy?”*

Under **SURGE-PY-027**, spatial constructability, infrastructure, and electrical metrics are unified into a single canonical engine using `CandidateEngineeringMetrics` (SURGE-PY-026). Under **SURGE-PY-029**, this engine integrates 25-year lifecycle NPV costing (SURGE-PY-028).

---

## Eligibility & Feasibility Screening

Before relative scoring occurs, candidates are filtered against strict feasibility criteria. To be eligible for ranking, a candidate must satisfy:

1. **AC Power Flow Convergence**: Pandapower load flow must converge without error.
2. **Electrical Compliance**: Zero voltage violations ($\Delta V \le 5\%$) and zero cable overloads ($\le 100\%$ rated ampacity).
3. **Topology Integrity**: The solved load flow structure must match the PNC graph topology.
4. **Canonical Metrics Extraction**: `CandidateEngineeringMetrics` must be fully populated (`engineering_metrics_available == True`).
5. **No Hard Exclusion Intersections**: Routes must not penetrate hard restricted areas.
6. **Cost Completeness (in Cost-Aware Mode)**: Candidate must possess a complete `CandidateLifecycleCost` assessment.

### Disqualified Candidates
Ineligible candidates receive `total_benefit_score = None` and cannot be selected as the recommended network. However, they remain in the output cohort so stakeholders can inspect their failure reasons via `disqualifications` (e.g., `CABLE_OVERLOAD`, `VOLTAGE_LIMIT_EXCEEDED`, `HARD_EXCLUSION_VIOLATION`).

### Context Invariance Rule
All candidates evaluated in a cohort must share identical `comparison_group_id` and `electrical_context_id`. Comparing networks evaluated under different turbine capacities or conductor libraries is structurally prohibited and rejected.

## Objective Groups & Metric Taxonomy

Scoring evaluates candidate metrics grouped into four canonical objective domains:

```mermaid
mindmap
  root((Candidate Scoring))
    Physical
      Route Length [m] (Lower is Better)
    Spatial
      Traversal Cost (Lower is Better)
      Affected Parcels (Lower is Better)
      Road Crossings (Lower is Better)
      Soft Constraint Overlap [m] (Lower is Better)
    Infrastructure
      Physical Pole Count (Lower is Better)
    Electrical
      Active Losses [MW] (Lower is Better)
      Cable Loading [%] (Lower is Better)
      Voltage Operating Margin [pu] (HIGHER is Better)
```

| Objective Group | Metric Identifier | Direction | Normalization Method | Description |
|---|---|---|---|---|
| **Physical** | `ROUTE_LENGTH` | Lower is better | Min-Max Inverse | Refined corridor length (m) |
| **Spatial** | `TRAVERSAL_COST` | Lower is better | Min-Max Inverse | Cost-surface routing resistance |
| **Spatial** | `AFFECTED_PARCELS` | Lower is better | Min-Max Inverse | Unique cadastral parcels crossed |
| **Spatial** | `ROAD_CROSSINGS` | Lower is better | Min-Max Inverse | Intersections with road layers |
| **Spatial** | `SOFT_CONSTRAINT_OVERLAP` | Lower is better | Min-Max Inverse | Length traversing soft penalty zones |
| **Infrastructure** | `PHYSICAL_POLES` | Lower is better | Min-Max Inverse | Deduplicated physical pole count |
| **Electrical** | `ACTIVE_LOSS` | Lower is better | Min-Max Inverse | 33 kV cable losses (MW) |
| **Electrical** | `CABLE_LOADING` | Lower is better | Min-Max Inverse | Maximum line current loading (%) |
| **Electrical** | `VOLTAGE_MARGIN` | **Higher is better** | Min-Max Direct | Headroom to nearest voltage limit |

*(Note: `ENVIRONMENTAL_OVERLAP_M2` is captured in PY-026 metrics but excluded from default scoring weights).*

## Mathematical Formulation & Normalization

Scoring uses a **"Higher is Better" Benefit Convention** bounded in $[0.0, 1.0]$. The best candidate for a metric receives a normalized benefit of $1.0$, while the worst receives $0.0$.

### 1. Cohort Min-Max Normalization

For **"Lower is Better"** metrics (length, losses, parcels, poles, cost):

$$\text{benefit}(x) = \frac{\max_{\text{cohort}}(x) - x}{\max_{\text{cohort}}(x) - \min_{\text{cohort}}(x)}$$

For **"Higher is Better"** metrics (voltage margin):

$$\text{benefit}(x) = \frac{x - \min_{\text{cohort}}(x)}{\max_{\text{cohort}}(x) - \min_{\text{cohort}}(x)}$$

### 2. Constant Range Behavior
If all eligible candidates in the cohort achieve the exact same value ($\max = \min$), `benefit = 0.0`. The weight is not artificially redistributed, preserving score stability.

### 3. Hierarchical Weighting
- **Group Weights**: $W_{\text{physical}} + W_{\text{spatial}} + W_{\text{infra}} + W_{\text{electrical}} = 1.0$
- **Subweights**: Within each multi-metric group, metric subweights must sum to $1.0$: $\sum w_i = 1.0$.
- **Metric Effective Weight**: $w_{\text{effective}, i} = W_{\text{group}} \times w_{\text{sub}, i}$
- **Group Benefit Score**: $S_{\text{group}} = \sum_i (w_{\text{sub}, i} \times \text{benefit}_i)$
- **Engineering Benefit Score**: $S_{\text{engineering}} = \sum (W_{\text{group}} \times S_{\text{group}})$

## Cost-Aware Policy Integration (SURGE-PY-029)

When financial parameters and a unit cost catalogue are provided, the engine computes the 25-year lifecycle net present value (NPV) $C_{\text{lifecycle}}$ for each candidate.

### Economic Benefit Normalization

$$\text{benefit}_{\text{economic}} = \frac{\max(C_{\text{lifecycle}}) - C_{\text{lifecycle}}}{\max(C_{\text{lifecycle}}) - \min(C_{\text{lifecycle}})}$$

### Combined Policy Score

$$S_{\text{total}} = w_{\text{engineering}} \cdot S_{\text{engineering}} + w_{\text{cost}} \cdot \text{benefit}_{\text{economic}}$$

where $w_{\text{engineering}} + w_{\text{cost}} = 1.0$.

---

## Tie-Breaking & Quantization

To prevent non-deterministic ranking caused by IEEE 754 floating-point jitter, all score benefits are quantized to **12 decimal places**.

### Deterministic Ranking Sequence

#### Unified Engineering Mode:
1. **Total Engineering Benefit Score** (Descending)
2. **Weighted Electrical Score Contribution** (Descending)
3. **Weighted Spatial Score Contribution** (Descending)
4. **Weighted Infrastructure Score Contribution** (Descending)
5. **Physical Route Length** (Ascending — shortest preferred)
6. **Active Power Loss** (Ascending — lowest loss preferred)
7. **Scenario ID** (Ascending — lexical fallback: `SCN-001` < `SCN-002`)

#### Cost-Aware Policy Mode:
1. **Total Combined Benefit Score** (Descending)
2. **Total Engineering Benefit Score** (Descending)
3. **Lifecycle Cost NPV** (Ascending — lowest cost preferred)
4. **Physical Route Length** (Ascending)
5. **Active Power Loss** (Ascending)
6. **Scenario ID** (Ascending)

## Explainability & Plain-Language Reasons

The recommendation engine provides auditable, human-readable rationale records in `RecommendationReason`:

1. **`BEST_METRIC`**: Emitted for each positively weighted, non-constant metric where the winning candidate achieved the top performance in the cohort.
2. **`GROUP_STRENGTH`**: Emitted when an entire objective group materially contributed to the candidate's victory ($W_{\text{group}} > 0$ and $S_{\text{group}} > 0$).
3. **`TRADE_OFF_ACCEPTED`**: Emitted if the winning candidate had a lower individual metric score compared to the ranked runner-up, explicitly documenting accepted engineering trade-offs (e.g., *“Selected route accepts 120m additional cable length to avoid 3 private land parcels and reduce peak loading by 4.2%”*).
4. **`BASELINE_IMPROVEMENT`**: Emitted comparing the winning scenario against `SCN-001 (baseline)`, detailing percentage reductions in length, losses, or costs.
